## Why

Most NZ:P co-op players are in the browser on Duckmath. The official Windows game can list those rooms with the right config, but it can't join them: Windows' TLS stack fails the browser handshake (`SEC_E_ALGORITHM_MISMATCH`). This repo fixes that with a 5-byte patch to the official exe, plus the config and data setup that makes the join work.

## Quick start

1. Download `nzportable-duck-<version>.zip` from [Releases](https://github.com/debug-cli/nzportable-duck/releases/latest) and extract it.
2. Pick a folder based on who hosts the room:
   - **Duckmath rooms** (most of them): `NZP-Duck`
   - **nzp.gay rooms**: `NZP-Web`
3. Add that host's two game files to the folder's `nzp\` folder. See [Game data](#game-data) below.
4. Run `nzportable64-dtlsclient.exe`.
5. Go to Co-operative, then the server browser, then refresh, and join an unlocked room.

> Don't trust a downloaded exe? Patch your own copy of the official nzp-team exe with `tools/patch.py`. It checks the hash before saving. See [TECHNICAL.md](TECHNICAL.md) for the exact bytes.

## Game data

Your files must match the room's host. If they don't, you get kicked with `Map model file does not match`.

| Host | game.pk3 | progs.pk3 |
|---|---|---|
| Duckmath | [nzp_game.pk3](https://pub-2d868f15a1824cc8a2ec51069ed41c6f.r2.dev/nzp_game.pk3) (71,785,249 B), renamed to `game.pk3` | `nzp/progs.pk3` from Duckmath's game page (458,237 B) |
| nzp.gay | [game.pk3](https://nzp.gay/nzp/game.pk3) (94,276,834 B) | [progs.pk3](https://nzp.gay/nzp/progs.pk3) (491,379 B) |

- Don't extract `.pk3` files. If the browser saves one as `.zip`, rename it back to `.pk3`.
- Sizes are as of 2026-11-09. They change when the hosts update.
- The Duckmath files are Duckmath's copy, not official nzp-team files. Duckmath hosts need them.

## Folder layout

```
NZP-Duck\
  nzportable64-dtlsclient.exe
  default.fmf          <- adds NZP-REBOOT-WEB to the server browser
  identity.pfx         <- RSA cert that Windows can sign with
  nzp\autoexec.cfg     <- turns on DTLS + WebRTC
  nzp\game.pk3         <- Duckmath
  nzp\progs.pk3        <- Duckmath
NZP-Web\
  (same, with nzp.gay's game.pk3 and progs.pk3)
```

## Troubleshooting

| You see | Cause | Fix |
|---|---|---|
| `SEC_E_ALGORITHM_MISMATCH` | Unpatched exe | Run `nzportable64-dtlsclient.exe` |
| `SCTP Abort: Protocol Violation [INIT malformed]` | SDL exe | Use the nosdl build |
| `Map model file does not match` | Wrong data for this host | Switch folders |
| `server requires a password` | Locked room | Pick another room |
| `ice state failed`, no `We can reach` | The network blocks UDP | Try another room or network |
| Empty server browser | Missing `protocolname` line | Use the included `default.fmf` |

**Still stuck?** Press `~`, type `net_ice_debug 2`, join, then type `condump joinlog`. Open a [join problem issue](https://github.com/debug-cli/nzportable-duck/issues/new?template=join-problem.yml) and attach `nzp\joinlog.txt`.

## How it works

| Problem | Fix |
|---|---|
| The browser doesn't list web rooms | `protocolname "NZP-REBOOT-WEB NZP-REBOOT"` in `default.fmf` |
| No WebRTC | `net_enable_dtls 1` and `net_ice_usewebrtc 1` |
| SDL exe sends SCTP tag 0 | Use the nosdl exe, which has a real RNG |
| Windows can't be a DTLS server | Patch `a=setup:actpass` to `a=setup:active`, so the exe acts as the client |
| Map mismatch | Use the host's own data |
